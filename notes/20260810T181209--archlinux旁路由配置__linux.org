* 原理

一台运行 Arch Linux 的小主机通过 WiFi 连接上游路由器, 同一局域网内的其他设
备将网关和 DNS 指向该主机, 流量经 mihomo TUN 透明代理分流: 国内直连、境外走
代理节点。本机自身代理不受影响, 下游设备零配置感知。

#+begin_src ascii

  上游路由器 (192.168.31.1, DHCP)
  │
  ├─ 本机 (192.168.31.194, mihomo)  ←─ WiFi
  │    ├─ 自身流量 → TUN → 分流
  │    └─ 转发流量 → MASQUERADE → TUN → 分流
  │
  └─ 其他设备 (网关/DNS = 192.168.31.194)
       └─ 经本机转发, 透明代理

#+end_src

旁路由与「主路由接管」的区别在于不改变现有网络拓扑, 只需按需修改终端设备的网
关设置即可。

* 环境

| 项目         | 说明                     |
|--------------|--------------------------|
| 操作系统     | Arch Linux               |
| 内核代理     | mihomo (v1.19.29)        |
| 上游路由器   | 小米路由器, 192.168.31.1 |
| 本机 IP      | 192.168.31.194 (WiFi)    |
| 包管理器     | pacman                    |
| 防火墙框架   | nftables                 |

* 安装 mihomo

#+begin_src sh
  pacman -S mihomo
#+end_src

systemd service 由包自带, 无需手写, 默认路径 /etc/mihomo。

** =/etc/sysctl.d/99-gateway.conf=

开启内核 IPv4/IPv6 转发, 使本机能够为其他设备路由流量。

#+begin_src conf :tangle /etc/sysctl.d/99-gateway.conf
  net.ipv4.ip_forward = 1
  net.ipv6.conf.all.forwarding = 1
#+end_src

** =/etc/nftables.conf=

MASQUERADE 规则。注意不要包含 mihomo 自身的 ~auto-redirect~ 规则 (由 mihomo
自行管理), 否则 ~nft -f~ 加载时会因语法错误使服务启动失败。

#+begin_src conf :tangle /etc/nftables.conf
  table inet nat {
      chain postrouting {
          type nat hook postrouting priority srcnat; policy accept;
          oifname "wlp1s0" masquerade
      }
  }
#+end_src

~wlp1s0~ 为本机的上游网络接口 (WiFi), 按实际情况修改。

* 操作步骤

1. 安装 mihomo:

   #+begin_src sh
     pacman -S mihomo
   #+end_src

2. 编辑 ~/etc/mihomo/config.yaml~, 确认两处旁路由关键配置:

   #+begin_src yaml
     find-process-mode: off
     dns.listen: ":53"
   #+end_src

3. 创建并应用内核转发配置:

   #+begin_src sh
     cat > /etc/sysctl.d/99-gateway.conf << 'EOF'
     net.ipv4.ip_forward = 1
     net.ipv6.conf.all.forwarding = 1
     EOF

     sysctl --system
   #+end_src

4. 配置 NAT (nftables):

   #+begin_src sh
     # 写入持久化规则
     cat > /etc/nftables.conf << 'EOF'
     table inet nat {
         chain postrouting {
             type nat hook postrouting priority srcnat; policy accept;
             oifname "wlp1s0" masquerade
         }
     }
     EOF

     # 启用并启动
     systemctl enable --now nftables
   #+end_src

   *踩坑提醒*: 不要用 ~nft list ruleset > /etc/nftables.conf~ 导出规则, 这会把
   mihomo 的 auto-redirect 规则也写进去, 其中的 ~redirect ... return~ 语法会被
   ~nft -f~ 拒绝, 导致 nftables.service 启动失败。

5. 启动 mihomo:

   #+begin_src sh
     systemctl enable --now mihomo
   #+end_src

* 踩坑记录

** nftables 启动失败: =redirect ... return= 语法错误

*原因*: 用 ~nft list ruleset > /etc/nftables.conf~ 导出时包含了 mihomo 的
~auto-redirect~ 规则, 其中 ~redirect~ 是终结指令, 后面不能跟 ~return~, ~nft -f~
加载文件时报错退出。

*解法*: 手动写 ~/etc/nftables.conf~, 只包含 ~nat postrouting masquerade~ 规则。

** mihomo 修改配置后不生效

*hup reload* (~systemctl reload mihomo~) 不会重新绑定 DNS 监听地址, 修改 ~dns.listen~
后必须执行 ~systemctl restart mihomo~。

** 客户端 DNS 不通

检查:

1. ~ss -tulnp | grep :53~ 是否显示 ~*:53~ (不是 ~127.0.0.1:5335~), 如果不是则重启 mihomo
2. 客户端能否 ping 通 ~192.168.31.194~
3. 本机防火墙是否放行 53 端口

** IPv6 泄漏

如果 ~ipv6.conf.all.forwarding~ 为 1 但客户端没配 IPv6 网关, IPv6 流量会绕过
mihomo 直连。两种处理方式:

1. (推荐) 完整配置: 同时设置客户端的 IPv4 + IPv6 网关/DNS 指向本机
2. 简单粗暴: 在 mihomo 中关闭 IPv6 (~ipv6: false~, ~dns.ipv6: false~)

** 是否需要 TProxy?

不需要。当前拓扑下 TUN ~auto-route~ + 策略路由表 ~2022~ 已经实现透明代理, TProxy
不会带来额外收益, 反而需要维护 iptables/nftables TPROXY 规则和 fwmark 路由表。
